# ESP-NOW 父节点认证 v1

2026-11-25，源码实现；尚未完成ESP-IDF构建及无线实物验收。
应用控制仍使用[MQTT/TLS与MUX1](../../v1/README.md)，不新增TCP业务入口。

## 信任和流程

子节点持有离线登记的授权服务P-256验证公钥；每台设备持有独立的父节点认证签名密钥。
非根节点签名身份与原TLS客户端证书SHA-256指纹、node_id、root_id和角色绑定。
根节点不作为MQTT客户端，使用单独登记的设备签名身份，经所选根节点的USB会话请求授权。
授权私钥只在主机；固件只嵌入该设备的auth.key和authority.pub，绝不嵌入authority.key。

1. Mesh-Lite扫描候选BSSID，非根角色的白名单回调默认返回NULL，并安排ESP-NOW挑战。
2. 子节点向该候选AP发随机128位nonce、自己的STA MAC和期望父层级。此时没有IP、未关联候选。
3. 候选必须已在本次启动获得自己的20秒中继租约，才为子节点挑战签名并请求在线授权。
   UGV/UAV通过自身证书限定的MQTT主题请求；根节点经USB请求。
4. 主机核对传输身份、清单当前授权、角色、根归属、证书绑定和设备签名，签发本次nonce的证明。
5. 候选将证明通过ESP-NOW两片发送给子节点；子节点独立验证主机签名和设备持钥签名，
   核对nonce、自己的STA、候选BSSID、所属根及父层级，5秒内收到才接受。
6. 候选加入有效集合，Mesh-Lite才获准选择。Micro的prefer/fixed还要求签名中的node_id与指定父节点一致。

AP可以一直广播。未认证父节点没有有效证明，不能使正常固件的下级放行。
Micro固定第4层，永不取得父节点资格；UGV/UAV分别只能选第1/2层父节点。

## 时间、重连与撤销

父节点每5秒申请一次自身新租约，子节点每约5秒生成新挑战并续验其候选。
租约截止点为子节点发出该挑战的单调时间加20秒，不是收到证明后再加20秒。
证明响应窗口5秒；两片重组窗口2秒；重试约500..599ms，不延长原挑战窗口。
该流程不依赖子节点尚未认证的UTC或网络时间。

未在期限内续验，子节点主动断开该父链路并重新扫描；STA/AP无线接口不因此整体关闭。
STA断开事件首先清除旧父节点证明，重新关联必须有新挑战，固件重启后缓存为空。
Bridge自动直连必须关闭；Mesh-Lite旧父节点快速重试次数设为0，重新扫描经认证白名单筛选。
主机每次签发重新读取清单；撤销后不再签发，即使Broker的旧ACL尚未重载或旧TLS会话仍存在。
已被子节点接受的证明最多保留20秒；再加约1秒的固件复核和Wi-Fi事件处理延迟，不能宣称瞬时撤销。
恢复服务后按当前证明重新入网、认证和续租，不要求手动重启解锁。

## 字节格式

所有ID为ASCII，最长32字节，右侧补0；多字节数字使用网络字节序；签名为P-256 ECDSA/SHA-256的
固定64字节r||s，各32字节大端，不使用ASN.1 DER签名字节。公钥为65字节SEC1非压缩点。

### 签发请求 PAR1（177字节）

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 4 | PAR1 |
| 4 | 1 | purpose：0自身中继租约，1对子节点挑战的证明 |
| 5 | 32 | 父节点node_id |
| 37 | 32 | root_id |
| 69 | 16 | 父节点本次parent_auth启动随机boot值 |
| 85 | 6 | 父节点AP BSSID |
| 91 | 16 | 本次nonce |
| 107 | 6 | 请求证明的子STA；purpose=0时为本机STA |
| 113 | 64 | 设备对前113字节的签名 |

### 授权证明（312字节）

| 偏移 | 长度 | 内容 |
| --- | --- | --- |
| 0 | 177 | 完整PAR1及设备签名 |
| 177 | 65 | 已登记设备签名公钥，由主机认证绑定 |
| 242 | 1 | 主机按清单确认的父层级1/2/3 |
| 243 | 1 | 租约秒数，固定20 |
| 244 | 4 | admission_revision |
| 248 | 64 | 授权服务对前248字节的签名 |

### ESP-NOW

复用Mesh-Lite ESP-NOW接收分发的预留type=200；直接发送带此前缀的独立缓冲，
不重注册全局接收回调、不复用第三方共享发送缓冲，也不修改第三方源码。

- PAC1挑战：`PAC1(4) | nonce(16) | child_sta(6) | expected_parent_level(1)`，共27字节。
  子STA单播到候选AP；含type前缀共28字节。
- PAF1证明片：`PAF1(4) | nonce(16) | part(1) | payload(156)`，共177字节。
  part只能为0或1；父AP单播到子STA；含type共178字节，兼容250字节ESP-NOW限制。
- 只接受匹配待处理nonce、源AP、目的STA的片；乱序可重组，冲突重复片清空重组状态，
  两片完整后才进行双重验签。未知片、超长片、过期片均不能放行。

同一时刻最多8个候选、8个下级挑战、8个待签请求，接收队列16项；队列满时拒绝/丢弃，等待新挑战。
主机单实例每秒最多签发32个请求，固件每秒最多处理24个认证无线事件。
密码运算、文件操作和发送不在Wi-Fi接收回调或候选回调中执行。

采用Mesh配置的同一信道和channel=0当前信道发送；扫描期间的收发时序必须实物验证。
不覆盖已有ESP-NOW peer的接口、LMK或加密设置；遇到不兼容peer返回失败而不绕过认证。
每台设备ESP-NOW peer数量受SDK限制，持续变更大量MAC可能耗尽peer表并需要维护恢复。

### MQTT与根USB

请求复用`mesh/v1/nodes/NODE/telemetry`，QoS1、不retain：

```json
{"v":1,"type":"parent.auth.request","proof":"base64(PAR1)"}
```

主机根据主题确定已认证node_id，并核验请求内身份和独立设备签名。响应使用同节点commands，QoS1、不retain：

```json
{"v":1,"type":"parent.auth.grant","proof":"base64(312-byte-grant)"}
```

请求base64为236字节，响应为416字节，JSON响应符合旧节点的512字节命令限制。
MQTT3.1.1实时转发可能清除RETAIN位；不把该位单独当作安全保证。存储后重放的retained消息忽略，
安全新鲜度由nonce、boot绑定和本机响应窗口保证。

根USB的READY低位值2协商NETWORK和父节点认证扩展。DATA分块协商使用独立的 [READY位](../../v1/README.md#根节点usb隧道-mux1)。类型11 PARENT_REQUEST和12 PARENT_GRANT
均为通道255、token/seq=0、当前epoch，分别承载177/312字节。
旧READY seq=1仍可传诊断，不能取得本扩展的根授权。根桥接只为配置所选root_id签发，
不能用根USB为UGV/UAV绕过MQTT认证。CRC不提供身份认证，设备签名和授权服务签名才是认证依据。

## 安全边界与上板证据

这是父节点资格验证，不是ESP-NOW链路加密，也不阻止修改过固件的子节点自行使用共享Wi-Fi密码入网。
后者仍受业务mTLS/ACL约束。无线重放不能通过新nonce验证，但攻击者实时转发整个认证交换的
虫洞/中继攻击不能仅凭BSSID和签名排除；本实现不提供物理距离、射频来源或抗干扰保证。
固定父节点校验签名node_id；MAC不是独立信任根。设备签名密钥被复制或主机授权私钥失窃另属密钥失陷。

必须上板确认：实际Mesh-Lite闭源核心在初次选择、断线恢复和回退路径均调用白名单，
禁用旧父快速重试生效，ESP-NOW扫描/收发和peer表与Mesh共存正常。
主机C函数测试使用假RTOS/无线接口和真实密码运算，不能替代这些证据。
