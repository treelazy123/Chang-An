# ESP-NOW逐层父节点认证

创建：2026-11-24；更新：2026-11-25。状态：源码链路已实现，主机验证已执行；未进行ESP-IDF构建、烧录和无线实物验收。

按用户确认的方案：各中继AP可持续广播，由下层节点在关联前主动验签。AP开关探针已移除，
不再作为前置条件；原“认证失败整机退网、锁定到重启”的简化机制也已删除。

## 当前链路

```text
主机：UGV Service + Mosquitto + 授权签发
                       │ USB：MUX1签名请求/响应
                   ugv-root 第1层
                       │ ESP-NOW验证root后，才关联Wi-Fi
                     UGV 第2层
                       │ ESP-NOW验证UGV后，才关联Wi-Fi
                     UAV 第3层
                       │ ESP-NOW验证UAV后，才关联Wi-Fi
                    Micro 第4层
```

Micro始终为叶子。普通业务仍是各节点到根主机Broker的端到端MQTT/TLS，中继不解密其他节点的TLS。
独立汽车终端通过本机HTTP/WebSocket使用UGV Service，不加入Mesh。

## 已实现的判断

- 所有非根角色的Mesh候选默认拒绝，缺少证明时只安排ESP-NOW挑战，不返回候选SSID。
- 候选先完成自身认证：UGV/UAV通过MQTT/TLS并取得主机中继租约，根C6通过USB及离线登记设备密钥取得根租约。
- 下层每次使用新的随机nonce，候选沿已认证通道申请本次nonce的主机签名授权，再通过ESP-NOW返回。
- 子节点验证授权服务签名和设备持钥签名，核对nonce、子STA、父BSSID、root和父层级后，才允许Mesh-Lite选择。
- Micro的auto/prefer/fixed均经过认证过滤；prefer/fixed还核对签名中的父node_id，不能只匹配MAC。
- 授权失效时子节点断开该父链路并重新选择；断线先清旧证明、禁用旧父快速直连。AP可继续广播。
- 主机每次签发读取当前清单和证书绑定，撤销后停止新签发，不等待Broker旧ACL重载。
- 新鲜度使用挑战发出时间和本地单调时钟；响应窗口5秒，租约最多20秒，约每5秒续验，不依赖未认证UTC。

完整字节格式、缓存界限、线程职责和安全边界见[协议v1](../protocols/parent-auth/v1/README.md)。

## 身份准备

```powershell
cd D:\changan\changan-mesh-system
uv run --locked python tools/provision_parent_auth.py
```

该命令只准备独立父节点认证身份，不改原TLS证书/私钥。重复运行校验并复用现有密钥，
不会覆盖；已有登记但丢失密钥会报错，不能通过删除目录重新签发来恢复。

默认处理启用且受信节点；本次已准备ugv-root、ugv-001、uav-001、uav-002、micro-001、micro-002。
尚无TLS证书且处于pending的ugv-002已跳过。需要预登记某个pending设备时，先按固件手册准备其TLS身份，
再显式执行`uv run --locked python tools/provision_parent_auth.py --node-id ugv-002`；这不会授予它中继权限。

新增文件位于secrets/parent-auth：

| 文件 | 用途 |
| --- | --- |
| authority.key | 主机授权签名私钥，不能烧进任何节点 |
| authority.pub | 固件预置的65字节P-256信任公钥 |
| nodes/NODE/auth.key、auth.pub | 各设备独立签名身份，包括根C6 |
| bindings.json | 公钥、所属root、角色和原TLS证书指纹绑定 |

固件只嵌入本机auth.key和authority.pub。完整保留这些身份文件；迁移时若目标已有不同父节点身份，工具拒绝覆盖。
缺少登记材料时CMake会停止并提示准备命令；不是自动降级到不认证联网。

## 更新和启动

需要更新根桥接、UGV Service以及所有参与测试的C6固件。新节点不会通过旧根桥接取得授权。
代理未操作现场服务或COM口；用户在原程序窗口正常停止旧实例后，按运行手册启动新版Broker、Service和根USB桥接。
既有MQTT主题权限可以复用，无需因本功能重新签发TLS证书。

按实物端口分别构建烧录，以下COM_*为占位符：

```powershell
uv run --locked python tools/lab.py --role ugv_root --node-id ugv-root --port COM_ROOT flash
uv run --locked python tools/lab.py --role ugv --node-id ugv-001 --port COM_UGV flash
uv run --locked python tools/lab.py --role uav --node-id uav-001 --port COM_UAV flash
uv run --locked python tools/lab.py --role micro_uav --node-id micro-001 --port COM_MICRO flash
```

旧缓存确实不匹配时按工具提示为该设备增加--reset-config；不要擦NVS或覆盖身份。
先启动根主机及根桥接，再按UGV、UAV、Micro顺序观察；root日志仍通过UART，不占MUX1原生USB。

正常日志应先看到上级`PARENT_AUTHORIZED`，再看到下级`PARENT_VERIFIED`，随后才是该下级的STA连接和MQTT认证。
主机拒绝签发会打印限频的`PARENT_AUTH_DENIED`；父证明过期会有`PARENT_LEASE_LOST`。
遥测parent_auth包含relay_authorized和relay_lease_ms；Micro本身的relay_authorized始终false。
业务ready与中继资格分开判断，刚ready但尚未取到中继授权时不能指定它为父节点。

## 用户实物验收

1. 正常四层链路：各层关联前出现父证明验证；逐节点ping/status/echo成功。
2. UAV不可信TLS证书：使用现有--tls-test-untrusted-client测试模式；AP可继续存在，
   但UAV无法取得中继授权，Micro不应关联该UAV。若Micro此前已连接，先重启Micro做全新关联测试。
3. 固定/优先父节点认证失败：固定模式保持离线；优先模式到期只回退到其他已认证、角色正确的候选。
4. 撤销UAV：主机立即拒绝新签发，Micro已缓存租约最长20秒后失效，再加固件复核/无线处理延迟；
   不把仍有AP广播或父节点驱动关联表暂未清理当作认证成功。
5. 关闭Broker或拔根USB：到期不再承认失效父链路；恢复后无需重启锁定解锁，应自动逐层重新认证。
6. UAV重启、Wi-Fi断开重连：旧证明不能直接复用，必须使用新nonce；错误签名、错root/层级/子STA和超时证明不放行。
7. 检查Mesh-Lite初始选择、自动重连和prefer回退均走白名单；确认关闭旧父快速重试确实生效。
8. 验证扫描/ESP-NOW收发与peer表共存、2MiB Flash余量、TLS及认证任务最小空闲堆/栈。

主机测试运行真实签名、隔离Broker和实际固件C函数，但无线接口/RTOS为替身，不能宣称已经通过上述上板测试。
本实现不提供抗射频干扰、抗实时虫洞转发或密钥被物理复制后的设备区分，详见协议安全边界。
